# Комплексное ревью zapret-ui

**Дата:** 20.10.2026  
**Коммит:** `9b384ce`  
**Метод:** три независимых прохода (безопасность/надёжность, архитектура/тесты,
продукт/UX/дистрибуция) + ручная проверка каждой находки по коду.  
**Предмет:** Windows-приложение Tauri 2 + Vue 3, управляющее runtime
`zapret-discord-youtube` как службой Windows.

---

## 1. Вердикт

Приложение **функционально сильнее большинства «pet»-проектов**: есть тесты ядра,
разделение модулей, обновление runtime, живой E2E-прогон и понятная предметная
область. Но до коммерческого продукта не хватает трёх вещей: **безопасности
целостности обновлений**, **надёжности транзакций** (обновление/бенч не должны
оставлять пользователя без обхода) и **продуктовой оболочки** (подтверждения,
онбординг, доступность, подпись, автообновление, логи).

| Область | Оценка | Комментарий |
|---|---|---|
| Безопасность | **3/10** | zip-slip, нет проверки целостности, запуск скачанного кода как SYSTEM, `csp: null` |
| Надёжность | **4/10** | падение посреди обновления/бенча оставляет без обхода; гонка записи конфига |
| UX | **5/10** | нет подтверждений, онбординга, доступности; результаты бенча без даты и легенды |
| Архитектура | **5/10** | `commands.rs` ~1075 строк, `App.vue` ~730 строк, stringly-typed ошибки |
| Тесты | **5/10** | 44 unit-теста ядра, 0 фронтенд-тестов, нет CI, транзакции не покрыты |
| Дистрибуция | **2/10** | exe не подписан, нет self-update, логов, crash-reporting, CI, CHANGELOG, лицензии |
| Документация | **4/10** | SPEC есть, но расходится с кодом (autostart, тесты, версии) |

## 2. P0 — исправлять до любого релиза

| # | Находка | Где | Влияние |
|---|---|---|---|
| P0-1 | **Zip-slip**: имя записи zip не санитизируется | `runtime.rs:95` | архив с `..\..\Windows\System32\…` пишется привилегированным процессом куда угодно |

Обе чинятся через `entry.enclosed_name()` и фиксированное локальное имя файла.

## 4. P2 — следующий цикл

**Надёжность/производительность**

- `get_state` каждые 4 с парсит 22 `.bat`, читает `config.json`/`service.bat` и
  запускает `sc` + `tasklist` (`commands.rs:97-160`). Это ~43 000 запусков
  процессов в сутки, в том числе когда окно скрыто в трее. Нужен кеш + пауза
  поллинга при скрытом окне.
- Обновление: нет таймаутов `reqwest`, нет лимита размера скачивания/распаковки
  (`runtime.rs:37-123`), нет crash-safe транзакции (маркер есть только у бенча).
- `engine.rs:130-145` удаляет **любые** службы `WinDivert`/`WinDivert14` и
  убивает любой `winws.exe` — коллатеральный ущерб другим инструментам.
- `.lock().unwrap()` в ~28 местах: паника в фоновом потоке отравляет мьютекс и
  ломает все команды до перезапуска.
- Нет единого лока операций: обновление, бенч и трей-старт/стоп могут
  пересекаться.
- `set_strategy` сохраняет имя до проверки существования → битый `last_strategy`
  переживает перезапуск.
- Сразу после `sc delete` идёт `sc create` — возможна гонка «marked for deletion».

**Архитектура/тесты**

- `commands.rs` — три модуля в одном: IPC, сессии бенча/поиска, транзакция
  обновления, watchdog. Выделить `session.rs`, `updater.rs`, `watchdog.rs`.
- `App.vue` — 730 строк без компонентов; `style.css` — 850 строк.
- Stringly-typed ошибки: внутренние английские строки и сырой текст `reqwest`
  попадают в UI. Нужен `thiserror`-тип с `user_message`/`detail`.
- Мёртвые IPC-команды и `Mutex<Engine>`: `restart`, `is_running`,
  `list_strategies`, `get_current_strategy`, `refresh_strategies`.
- `types.ts` руками дублирует serde-структуры (ts-rs/specta).
- Нет CI, rustfmt/clippy/eslint/prettier конфигов, CHANGELOG, `[profile.release]`
  (lto/strip), `authors = ["you"]`.
- Нет фронтенд-тестов; транзакции (`extract_zip`, `apply_update`, сессии) не
  покрыты — именно там живут P1.

**UX/доступность**

- Нет `:focus-visible`; сгенерированные стратегии — `div` без клавиатуры;
  иконки без `aria-label`; `--text-3` на карточке даёт ~3.1:1 (< 4.5:1).
- `refresh()` без `try/catch`; ошибка → вечное «Загрузка…».
- Тосты ошибок и обновлений в одном слоте, перекрывают друг друга, без
  автоскрытия и severity.
- Результаты бенча: нет даты/возраста, легенды D/Y/C, числа измеренных хостов;
  одиночный замер без предупреждения о шуме; строки без данных не помечены.
- Лейблы: «эксперим.» рядом с «кандидатов» читается как одна фраза;
  «Проверить текущую» не говорит, что именно проверяется.
- 720×520: две колонки + вложенные скроллы, видно 2 строки стратегий.
- Закрытие в трей без объяснения; в трее нет статуса и пункта обновлений.
- Окно может открыться за пределами экрана (наблюдалось `y = -855` на
  multi-monitor).

**Дистрибуция/юридика**

- Версия `1.0.0` в трёх файлах, в UI показывается версия runtime, а не
  приложения; нет CHANGELOG.
- Нет `LICENSE`, EULA, privacy, third-party notices (zapret, WinDivert, Tauri,
  curl).
- `csp: null`; неиспользуемый `tauri-plugin-opener` и `opener:default`.
- README/SPEC расходятся с кодом (Run key vs Планировщик, дочерний процесс vs
  служба, число тестов).

## 5. P3 — полировка

- Мёртвый файл `query` в корне репозитория.
- `open_runtime_folder` запускает `explorer` от админа.
- `deleteGenerated` без undo и с кнопкой 18×18.

## 6. План ремедиации

**Фаза 0 — безопасность (блокер релиза).** P0-1, P0-2; P1-1 (hash из GitHub
asset `digest` + проверка `winws.exe`), P1-3 (абсолютные пути System32), P1-4
(атомарная запись конфига), P1-2 (валидация `generated.json` при применении).

**Фаза 1 — надёжность.** P1-5/P1-6 (RAII-восстановление обхода), P1-12
(логи + crash-reporting + support bundle), таймауты/лимиты скачивания,
единый лок операций, кеш `get_state`, проверка «наш ли» драйвер WinDivert,
`sc delete/create` с ретраем.

**Фаза 2 — продуктовая оболочка (этот цикл).** Рефакторинг UI по образцу
DiscordRoleChecker: дизайн-токены, панели с шагами, компоненты, модальные
подтверждения, тосты, онбординг, доступность, адаптивность, доверие к
результатам бенча, запрет неожиданного применения/перезапуска.

**Фаза 3 — дистрибуция.** Подпись exe, `tauri-plugin-updater` + манифест,
CI на GitHub Actions (cargo test/clippy, vue-tsc, tauri build), CHANGELOG,
версия приложения в UI, лицензия/EULA/privacy, публичный релизный процесс.

## 8. Статус после v1.1.0

**Закрыто в этом цикле:**

- **P0-1/P0-2**: `entry.enclosed_name()` в `extract_zip`, фиксированное имя
  `release.zip` вместо имени ассета; тест на zip-slip.
- **P1-3**: все системные утилиты (`sc`, `reg`, `net`, `taskkill`, `tasklist`,
  `netsh`, `schtasks`, `curl`, `explorer`) вызываются из `%SystemRoot%\System32`
  через `sys.rs`.
- **P1-4**: `config.json` пишется атомарно (tmp + rename); `get_state` обновляет
  версию runtime в памяти, а не перечитывает файл.
- **P1-5/P1-6**: ошибка обновления/бенча восстанавливает прежнюю стратегию;
  ошибка восстановления теперь попадает в текст ошибки, а не теряется.
- **P1-7/P1-8/P1-9/P1-10**: подтверждения полной проверки/подбора (с чекбоксом
  автоприменения), остановки, обновления и удаления; клик по строке только выбирает
  стратегию, применение — отдельной кнопкой; онбординг runtime в панели «Подключение».
- **P1-1 (частично)**: проверка `sha256`-digest ассета, если GitHub его публикует.
- **P2 UX**: панели с шагами, дизайн-токены, компоненты, тосты с severity,
  фокус-стили, контраст, клавиатурная навигация, адаптивность < 980 px, дата/легенда
  результатов, разделение «Проверка»/«Подбор», восстановление окна на видимый монитор,
  пауза polling при скрытом окне и во время прогона.
- **Архитектура UI**: `App.vue` ~80 строк, компоненты, `store.ts`; удалены мёртвые
  IPC-команды и `Mutex<Engine>`; `opener`-плагин и permission удалены; CSP задан.

**Осталось (следующие циклы):**

- **P1-2**: запрет исполнения пользовательских файлов как SYSTEM глубже, чем
  валидация `generated.json` (подпись/allow-list аргументов, проверка `winws.exe`).
- **P1-11/P1-12**: подпись exe, self-update, логи, crash-reporting, support bundle.
- **P2**: таймауты/лимиты скачивания уже есть; остаются кеш `get_state`, «наш ли»

## 9. Повторное ревью после v1.1.0

Диапазон: `9b384ce..HEAD` (UI-рефакторинг, безопасность, нативный заголовок,
фикс панелей). Найдено и исправлено:

- **Авто-проверка обновлений была отключена** после переезда состояния в `store.ts` —
  восстановлена в `initStore` (теперь «Установлена последняя версия» появляется сама).
- **Watchdog поднимал обход после ручной остановки** — проверяет, установлена ли служба;
  если пользователь её удалил, откат не выполняется.
- **Неудачное переключение стратегии оставляло без обхода** — `set_strategy` /
  `apply_candidate` откатывают конфиг и службу, ошибка отката попадает в текст.
- **Ошибка обновления перезапускала здоровый обход** — восстановление только если служба
  действительно остановлена; ошибка восстановления больше не теряется.
- **Параллельные обновления** — флаг `update_running` и уникальный staging-каталог для zip.
- **`stop` / `autostart::remove`** больше не рапортуют успех при неудаче: ждут исчезновения
  службы/записи и возвращают ошибку.
- **Polling** — защита от гонки ответов (sequence), у `benchRunning` один владелец,
  пауза при скрытом окне.
- **UI-мелочи** — клавиатура на вложенных кнопках строки, повторный confirm,
  `busy` для выбора без запуска, единый контракт `Toggle`, достижимый брейкпоинт 760.
- **Открытие папки runtime** — после ужесточения путей `explorer.exe` ошибочно искался
  в `System32` (его там нет) и кнопка падала с `os error 2`. Заменено на стандартный
  `ShellExecuteW("open", path)`, не зависящий от расположения оболочки.
- **Документация** — трей-статус и подтверждение остановки из трея честно перенесены
  в «осталось» (меню трея — явное действие).

Остаётся: подпись/self-update/логи/CI, трей-статус, «наш ли» драйвер WinDivert,
кеш `get_state`, фронтенд-тесты.
